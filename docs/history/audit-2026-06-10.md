# Memento Vault Audit — 2026-06-10

Multi-agent audit of architecture, weaknesses, and Claude/Pi parity, cross-referenced
against all 39 open GitHub issues. Six parallel subsystem readers (Claude lifecycle,
Pi lifecycle, shared core, search/store/sync, install/distribution, live triage
failure), followed by a parity analysis and an issue gap analysis. The live triage
failure was root-caused with an actual reproduction; the highest-impact code claims
in this report were individually re-verified against the code on disk. Findings are
written to be convertible into tickets — see [Recommended tickets](#recommended-tickets).

## How it works today (one paragraph)

The shared core is the `memento/` Python package: `lifecycle.py` holds the host-agnostic
primitives (briefing, recall, tool-context, capture, session-context), `store.py`/`search.py`
the vault I/O and retrieval pipeline, `llm.py` the headless-LLM abstraction, `mcp_server.py`
the MCP surface. **Claude Code** consumes it through thin Python hooks installed into
`~/.claude/hooks`: SessionStart briefing → UserPromptSubmit recall → PreToolUse(Read)
tool-context → SessionEnd triage (fleeting line + project index always; LLM structured-note
extraction for substantial sessions; auto-commit + reindex + inception trigger).
**Pi** consumes it through a TypeScript extension (`extensions/memento.ts`) shelling out to
`memento/pi_bridge.py`: briefing/recall on `before_agent_start`, optional tool-context on
`tool_result`, and a *queue-then-curate* capture model — lifecycle events append raw
summaries to a JSONL queue which `/memento-process` later feeds to a headless `pi` curator
via `memento-process-worker.mjs`.

## TL;DR — top findings

1. **(P0, live, reproduced)** Structured-note triage is failing 12/15 attempts because the
   full raw transcript is embedded in the LLM prompt with **no size cap**; >~700KB
   transcripts exceed sonnet's context window. The real error ("Prompt is too long") is
   printed to stdout, which `llm.py`'s error path discards — the health log records a
   misleading stale-tool warning or a generic exit-code message. Failed sessions are
   **permanently lost** (no retry, no spool, SessionEnd fires once). The most valuable
   sessions are exactly the ones that fail.
2. **(P0, parity)** Pi has **no automatic durable capture**: `autoCapture` defaults to
   false, lifecycle events only queue raw summaries, nothing writes fleeting/project-index
   history, and `processQueueOnSessionClose` is parsed but read by no handler (dead
   config). A Pi-only user accumulates nothing by default. (#33 / #74 cover slices of
   this, not the whole.)
3. **(P0, parity)** Pi-written notes are **never committed and never reindexed** — zero
   `vault-commit.sh`/reindex call sites in `pi_bridge.py`, `memento.ts`, or the worker.
   Notes sit uncommitted and invisible to BM25 recall until a Claude session happens to
   sweep them up.
4. **(P1)** The deferred-briefing machinery is broken on both hosts in complementary ways:
   Claude's background worker spawn resolves to a nonexistent path in the installed layout
   (`~/.claude/hooks/hooks/vault-briefing.py`), and Pi spawns deferred searches it never
   consumes — whose "ready" results then **leak into the next Claude session in any
   project** (single global file, no session/project guard).
5. **(P0, release)** Issue #90 (brew install broken on macOS bash 3.2) is fixed on main
   (`4fad781`) but **unreleased** — the tap still ships broken v4.1.0. No shell-syntax or
   install-execution gate exists to catch this class (#52/#54 are open for exactly this).

## P0 live failure: triage structured-notes extraction

Root cause chain (verified by running the exact live command against the failing session's
transcript):

- `memento/adapters/__init__.py:82` renders a Claude transcript as literally
  `open(transcript_path).read()` — the raw multi-MB JSONL, no truncation. No size cap
  exists anywhere in the prompt path (`memento-triage.py:399-414`, `llm.py`).
- `llm.py:150-175` runs `claude --print --model sonnet …` with the prompt on stdin.
  For 780KB–2.2MB transcripts the CLI exits 1 in ~3s with `Prompt is too long` **on
  stdout**. All failures in the last 24h are ≥780KB; all successes ≤656KB.
- `llm.py:92-108` (`_run_cli`): in the error branch, stdout is only consulted when
  `output_path is not None` (codex-style backends). For the claude backend the message is
  `result.stderr.strip() or "LLM command failed with exit code 1"` — the actual error
  never reaches the health log.
- stderr is polluted by a harmless warning on *every* run: `CLAUDE_HEADLESS_DISALLOWED_TOOLS`
  (`llm.py:125`) still lists `MultiEdit`, a tool removed from current Claude Code. Earlier
  health-log entries recorded this warning as the "error".
- No retry: `_claude_complete` is single-shot (the codex backend retries 5×,
  `llm.py:178-198`). `process_structured_notes` logs and returns 0; the transcript is never
  reprocessed. Notes from failed sessions are permanently lost.
- Surfacing: the only user signal is one `[vault] WARN` line at SessionStart
  (`lifecycle.py:171-209`); its hint heuristics can't name this failure mode (the real
  message never reaches the log).
- Bonus finding: the installed `~/.claude/hooks/memento-triage.py` had drifted older than
  the repo copy — installed-vs-repo drift has no detection.

**Fixes (one ticket each, ordered):** (1) cap/summarize transcript input — chunk or
head+tail truncate to a token budget before prompting; (2) include stdout in the error
branch of `_run_cli`; (3) remove `MultiEdit` from the disallowed-tools list; (4) add a
retry/spool for failed local extractions (the remote path already has spool+retry —
reuse the envelope); (5) teach the health warning to surface the recorded error text.

## Pi ↔ Claude parity

Both hosts share the same core for **briefing, recall, and tool-context builders** — the
read side is architecturally at parity. Everything around the edges diverges:

| Capability | Claude | Pi | Parity |
|---|---|---|---|
| Session-start briefing | hook, uncapped, **experimental-only install** | default-on, 4000-char cap | ≈ |
| Deferred briefing/deep recall | consumes, but worker spawn path broken installed | spawns, never consumes; leaks cross-host | ✗ |
| Prompt-time recall | hook, 5s timeout, experimental-only | default-on, 15s timeout | ≈ |
| Tool-context | pre-read inject, default-on (experimental) | post-read append, default-off; status UI misreports | ✗ |
| Automatic session capture | always: fleeting + project index + structured notes | nothing by default; queue-only behind `autoCapture` | ✗ |
| Structured note schema | typed, tags, certainty 1–5, supersedes | hardcoded `type=session`, no certainty | ✗ |
| Commit after capture | immediate + sentinel-gated | none | ✗ |
| Reindex after capture | timer-scheduled | none | ✗ |
| Failure telemetry | always-on triage-health.jsonl + briefing WARN | none (transient footer string only) | ✗ |
| Retry/dead-letter | remote spool + sync-retry; codex 5× retry | failed captures dropped or re-run without dedup guard | ✗ |
| Orphan-session sweeper | yes (`memento-sweeper.py`) | none; crashed Pi sessions lost | ✗ |
| Inception auto-trigger | from triage | none (manual skill only) | ✗ |
| Queue review UX | none | rich (dashboard, dry-run, process-status) | ✗ (Claude behind) |
| Remote vault | read + write w/ spool | read-only; captures always local | ✗ |
| Install validation | settings merge + module verification | none (hardcoded `python3`, no probe) | ✗ |
| Skills | installed to `~/.claude/skills` | `skills/generic` via package.json | ≈ (dup copies drift hazard) |

Key parity defects beyond the TL;DR items:

- **Opposite out-of-box defaults**: a stable (non-`--experimental`) Claude install captures
  but never injects context; a default Pi install injects context but never captures.
  Mirror-image gaps (`install.sh:271-272`, `install_helpers.py:137-166`, `memento.ts:43-47`).
- **Three divergent capture schemas**: Claude triage (typed + certainty), Pi `_capture`
  (`note_type='session'`, no certainty, `pi_bridge.py:484-494`), MCP `memento_capture`
  (`discovery`, certainty=2, `mcp_server.py:882-897`). Downstream certainty-based defrag
  and search weighting treat Pi notes as second-class.
- **Pi failures are invisible**: zero `log_triage_health` call sites on the Pi side. A
  broken `python3` silently disables briefing, recall, tool-context AND capture with no
  trace on disk (`memento.ts:172-228`).
- **Pi queue data loss race**: queue appends are unlocked read-modify-write with plain
  `write_text` (`pi_bridge.py:154-156, 477-479`); `_queue_process_finalize` re-writes the
  filtered file (`:1066, :1114-1115`) — a capture appended by a concurrent Pi session in
  that window is silently deleted.
- **Curator fragility / duplicate risk**: result extraction is a greedy regex over raw
  stdout (`memento-process-worker.mjs:83-87`); a parse failure marks the group failed
  *after* notes may have been written, and failed groups re-run with only prompt-level
  dedup. The recursion guard is half-built: `MEMENTO_PI_PROCESSOR` is set but never read;
  `metadata.memento_processor` is filtered on but never written (`pi_bridge.py:644`).
- **No Pi transcript adapter**: `adapters/__init__.py:113-117` knows Claude JSONL and
  OpenCode SQLite only, so Pi sessions can never flow through the triage/sweeper pipeline
  even if wired. This blocks the cleanest parity path (#74's SessionEnd-style triage).
- **Capture gate (#91 area) is leaky**: with no manual-capture baseline every lifecycle
  event queues; after baseline the `_FILE_EDIT_SIGNAL` regex matches nearly any coding
  summary; `manual_capture_body_hash` is stored but never compared (`pi_bridge.py:242,
  254-255`).
- **Cross-host shared runtime state is unlocked**: recall dedup (`last-recall.json`),
  deferred files, and the tool-context cache are global per-user files mutated by Claude
  hooks, the Pi bridge, and MCP with no locking or session scoping — Pi recall suppresses
  notes in concurrent Claude sessions and vice versa (`lifecycle.py:1927-1931, 897-954`).
- **session-context counts the legacy queue**: `lifecycle.py:1702` reads
  `vault/queue/pi-captures.jsonl`; the queue migrated to XDG state
  (`pi_bridge.py:68-79`) — the count is stale/zero post-migration.

### Recommended parity direction

The owner's goal is "both at parity, working the same way." The cleanest convergence is
the one #74 already names: **make Pi session-end behave like Claude triage** — write
fleeting + project-index entries unconditionally, run the same substantiality gates, and
route structured extraction through the same `process_structured_notes`/`write_note`
path (vault lock, typed schema, certainty), followed by the same commit + reindex +
inception hooks. Keep Pi's queue/dashboard as an optional review layer on top, and port
it to Claude later if review-before-write proves valuable (rather than maintaining
opposite philosophies). Prerequisites: a Pi transcript adapter, Pi-side health telemetry,
and commit/reindex calls in the bridge write path.

## Other weaknesses worth tickets

**Search / store / sync** (high): embedded-index corruption discovered after the first
search is never repaired — search silently returns empty forever; sync conflicts are
detected but permanently unresolvable (locally edited notes never propagate; a lost
ledger re-pushes everything as duplicates); an embedding provider/dimension change
silently breaks vector search permanently. Medium: `indexer.scan_and_index` (the staleness
repair) has no production caller; tokenizer-fallback embeddings poison the index;
single-note sync prints "Synced" on failure and exits 0; project filter does raw string
prefix matching without a path-separator boundary; QMD availability probe spawns a real
subprocess twice per search call.

**Claude lifecycle** (high): `exchange_count` counts tool_result round-trips, inflating
substantiality scoring (this also feeds the oversized-transcript problem); the
explicit-project recall filter treats any sentence-initial capitalized word as a project
name and drops valid notes. Medium: commit/reindex timers race the LLM worker; fleeting
and project-index writes are unlocked and non-atomic; in-flight payloads/sentinels can be
committed into vault git history; `vault-commit.sh` resolves the vault differently from
Python config; hook timeout budgets (2–5s) are smaller than the work the hooks can do,
and vault-recall deletes the deferred file before output is guaranteed.

**Install / distribution** (high): the `curl|bash` bootstrap dies at unguarded interactive
prompts on first install. Medium: `uninstall.sh` removes a stale subset of what install.sh
installs; `merge_settings` rewrites *any* user hook command under `~/.claude/hooks/`;
corrupt settings.json aborts install mid-way; the brew release process is manual,
two-repo, placeholder-sha256; Pi/OpenCode get zero installer support (Pi relies on
`pi install` + a hardcoded `python3` with no validation).

**Core** (medium): codex/gemini backends pass the prompt via argv (ARG_MAX overflow risk)
and ignore the scaled timeout; the simple-YAML fallback parser coerces floats for only 3
whitelisted keys (other float overrides become strings and can crash recall); the
module-level FastMCP app skips the transcript-path restriction and bearer auth enforced
in `main()`.

**Testing**: zero TypeScript-side tests (memento.ts config layering, event wiring,
worker parsing — including the unused `--fake-curator` hook built for exactly this);
no tests for `vault-commit.sh`, `wait-and-commit.py`, or the deferred-worker spawn path
(which would have caught the installed-layout bug).

# Part 2 — Deep dive: capture quality, injection waste, LLM cost (2026-06-10)

Follow-up investigation into three owner-reported problems: (A) Pi capture quality is
subpar vs Claude, (B) per-turn read-path injections are largely trash and unused,
(C) headless `claude` won't be cost-effective for programmatic use. Four parallel
investigators sampled the **live vault** (2,560 notes), the **Pi capture queue**, the
**15 most recent substantial transcripts on each host**, and all LLM call sites.
Load-bearing numbers and code claims were independently re-verified.

## A. Why Pi capture quality is subpar

Measured gap: on a 30-note random sample per origin, **~60% of Pi-origin notes are
well-formed atomic insights vs ~97% for Claude triage**. 695/709 (98%) Pi notes are
untyped `type: session`; only 9% carry certainty. Four compounding causes, ranked:

1. **Historical raw-dump pollution (most visible).** A since-removed `_queue_flush`
   path (added `18ac16a`, removed `3d0bc67` on 2026-05-24) wrote queued lifecycle
   bodies verbatim into the vault. **107 `*-candidate-capture-*.md` notes** (15% of
   Pi notes, all stamped 2026-05-24 20:05) are raw JSON message/thinking dumps —
   including encrypted reasoning ciphertext. They are still indexed and actively
   surface in retrieval on **both** hosts (see B). The writing code is gone; the
   data cleanup never happened.
2. **Garbage input to the queue.** `summarizeRecord` (`extensions/memento.ts:157-164`)
   builds capture bodies as `JSON.stringify(content).slice(0,500)` over the last 8
   messages with **no filtering of thinking blocks** — verified: 1,121/1,536 (73%) of
   the current queue backlog bodies contain `"type":"thinking"` JSON. Ironically
   `pi_bridge._clean_transcript` already knows how to skip thinking blocks; the TS
   side never got the same treatment. `agent_end` fires per turn (one session has 60
   queued captures), and the bae06e0 gate only suppresses *after* a manual-capture
   baseline exists.
3. **Output contract can't express quality.** Pi's `memento_capture` tool takes only
   `title/body/queue` (`memento.ts:602-608`); `pi_bridge._capture` hardcodes
   `note_type='session'`, no certainty. The curator literally writes
   `certainty: 4` as plain body text (57 notes) because there's no field for it.
   Claude triage enforces a typed JSON contract before `write_note`. (Part 1 ticket
   #11 covers this; the data above quantifies why it matters.)
4. **Curator prompt defects.** `memento-process-worker.mjs:54` instructs the model to
   preserve session metadata in note bodies → 28% of Pi notes open with session-path/
   capture-ID blobs that degrade readability, snippets, and embeddings. Dedup relies
   on voluntary `memento_search` calls → 13 duplicate clusters (one decision exists
   7×). Claude triage instead injects existing note titles into the prompt.

Secondary: 33% of curated groups (41/126 across 92 runs) had **no transcript** in the
curator packet (28 no-session, 11 over the 2MB cap) — those are curated from the
500-char JSON fragments alone; and the curator model is unpinned
(`processQueueModel: null` → whatever pi's default is; currently gpt-5.5 via the
Codex subscription).

## B. Injection waste — measured on both hosts

| Metric (15 most recent substantial sessions each) | Pi | Claude |
|---|---|---|
| Injections / user turn | 0.61 (101/165) | 0.37 (57/153) |
| Injected volume | ~1.1KB/session | ~280 tokens/session |
| Plausibly relevant (sampled) | ~26% | ~30-40% |
| Outright junk (raw dumps, log lines, bare titles) | ~26% | part of ~60-70% junk+off-topic |
| Injected content demonstrably used by the agent | 2/15 sessions (recall titles only); **0/64 tool-context uses** | **0/15 sessions**, 1 unrelated memento call |
| Same-note repeat injections | 19/101 within-session; worse cross-session | identical 5-note block in 4 sessions |

**Verdict: shared core problem, Pi-specific amplifier.** The junk classes are
identical on both hosts — candidate-capture dumps injected verbatim
(`pi-session-candidate-capture-3/-67/-85`), daily-note session-log lines with bare
UUIDs, truncated project-map/branch-index dumps, wrong-project bleed (personal-blog
notes into rondo sessions; beislid/fundid notes into agenticfootball sessions).
Claude's delivery gates (caps, min_score, 3-prompt dedup, hook timeouts) contain the
*volume*; they do nothing for *relevance*. And on the observed sample, essentially
**none of it changes agent behavior** — tool-context in particular is 0-for-64.

Root causes, ranked:

1. **Pi bridge cwd bug (critical, Pi-only).** The bridge subprocess runs with
   `cwd=<memento-vault repo>` (`memento.ts:182,201`) and the extension passes the Read
   tool's raw, often **relative** path. `build_tool_context` receives the real session
   `--cwd` but never uses it: `lifecycle.py:2229` calls `os.path.realpath(file_path)`,
   which resolves relative paths against the *process* cwd. So `.beislid/workflow.md`
   in ANY project resolves into the memento-vault repo, producing the query
   `"personal memento vault workflow"` for every project — explaining the
   most-repeated wrong-project injections. **Fix in `build_tool_context`: join
   `cwd`/`file_path` before realpath** (the cwd is already passed; it's just ignored).
2. **Vault pollution is in the index.** The 107 raw dumps rank in BM25 because they
   literally quote skill/file paths; they were observed injected into both Pi and
   Claude sessions. Cleanup is a data task, not a code task.
3. **Per-directory tool-context cache: no TTL, shared globally.** Poisoned entries
   replay forever — the live cache pins `memento-vault/docs` to two candidate-capture
   dumps; 17 candidate-capture references in the cache file (`lifecycle.py:2245-2282`).
4. **No quality signal in ranking; untagged notes bypass the project filter.**
   `enhance_results` weighs decay/PageRank/PPR but never note type, certainty, or
   source; `filter_by_project` (search.py:654) passes any note *without* a `project:`
   field as "general knowledge" — which is exactly the junk (candidate dumps, daily
   notes, personal-blog notes, branch-index notes).
5. **Dedup design gaps (both hosts).** Recall dedup is one global last-top-path slot
   for 3 prompts → identical blocks recur across sessions and hosts; tool-context
   dedup is keyed by session_id, which resets on session resume (verified: one
   transcript with 2 sessionIds got 3 contexts injected twice).
6. **The briefing WARN is itself dead-weight injection**: 31/31 sampled briefings
   (both hosts) carried the triage-failure warning — re-injected every session for
   days, never actioned.

The gates themselves work: `should_skip_recall` suppressed recall on 87% of Pi turns,
the 4000-char Pi cap and Claude's per-session caps behave as designed. This is a
content/ranking problem, not a throttling problem.

## C. LLM backend cost strategy

Inventory (verified against `llm.py` and live config): **only triage structured-notes
uses headless `claude`** (default backend, `agent_model: sonnet`), at ~11.5 calls/day
(~350/mo) with uncapped transcripts — and a **52% June failure rate** (118 attempts,
62 LLM failures; the 32 entries blaming a "MultiEdit" deny rule are misattributed
stderr noise — the underlying cause is prompt-too-long, per Part 1's reproduction).
Everything else is already off claude: inception → codex backend ($0, subscription),
deep recall → codex default (~1-2K-token prompts), Pi curator → `pi -p` on
openai-codex/gpt-5.5 ($0 marginal, and it needs tool-calling, not a completion API),
concierge → interactive Haiku subagent. Gemini/ollama are not installed; those
backends are dead code on this machine.

Recommended strategy:

- **Keystone: the transcript size cap (Part 1 ticket #1).** Median recent rendered
  transcript is 2.6MB (~660K tokens), p90 3.3MB. A ~50-100K-token cap fixes the
  current failures AND is a hard prerequisite for every cheaper backend (Haiku's 200K
  context; codex's 1MB ARG_MAX).
- **Primary: move triage to the codex backend** (proven for inception, $0/mo) after
  two `llm.py` fixes: `_codex_complete` passes the whole prompt as a single argv
  element (`llm.py:187` — ARG_MAX on this Mac is exactly 1,048,576 bytes) → switch to
  stdin or @file; and it inherits `_run_cli`'s default 30s timeout because
  `llm_complete` only scales timeouts for the claude backend (`llm.py:268`) → pass
  the scaled timeout through. Same argv bug exists in `_gemini_complete`.
- **Alternative: `anthropic-api` backend + `claude-haiku-4-5`** ($1/$5 per MTok):
  ~$0.05-0.09/call ≈ **$18-32/mo** at current volume, halvable to ~$9-16/mo via the
  Batch API (triage is detached and latency-tolerant). Needs hardening first: no
  retry on 429/5xx, fixed 30s timeout, `max_tokens=4096` hardcoded; consider
  structured outputs (json_schema) to kill the 14% parse_empty class.
- **Hygiene regardless of path:** remove stale `MultiEdit` from
  `CLAUDE_HEADLESS_DISALLOWED_TOOLS` (`llm.py:125`); record backend+model+prompt_bytes
  in triage-health entries so post-migration failure and cost are measurable.

Net: $0/mo (all-codex) or ~$10-30/mo (Haiku API for triage), versus today's
subscription-quota burn at a 52% failure rate.
